Structure

Usually, each folder in the root of the website is a core (but not necessarily).
A core is a collection of classes, units, templates, and a virtual root folder.
The framework itself is a core, your own folder will also be a core (you need to create it), each core should be stored in a separate repository.

In the simple case, you will have only two cores, for example: /BlackFox for the framework and /Site for your project.
It is possible to add additional cores.
All active cores need to be registered in the /config.php file (the 'cores' key).

The following folders may be located inside a core:

  • classes — contains classes
  • units — contains unit folders
  • root — virtual server root
  • templates — contains templates folders

Core

A core is a structural entity — a folder with the file Core.php and other files, including php-classes. The core name is the same as the folder name and namespace. Usually, one top-level namespace without nesting is used.

File Core.php must contain a descendant class of BlackFox\ACore with class name {YourCoreName}\Core and namespace equal to the core name:

namespace Example; class Core extends \BlackFox\ACore { public function GetScheme() {/* ... */} public function Upgrade() {/* ... */} public function Load() {/* ... */} public function Menu() {/* ... */} }
GetScheme
should return an instance of the class Scheme
Upgrade
called when installing or upgrading a core, use it to synchronize the structure of tables and other amendments (see descendants for an example)
Load
always called if the core is active
Menu
called by the admin menu unit, should return an array describing the administrative menu section (see descendants for an example)

Autoload classes

By default, the core scans its own subfolders classes and units, looks for any php-files in them and registers them as classes with the same name in the namespace of the core. Scan depth varies:

  • classes — all subfolders are scanned, unlimited nesting
  • units — scanned one nested subfolder deep

Thus, when developing your own core, place classes in the subfolder classes, units in the subfolder units, name files the same as the classes inside them, and they will be automatically registered in the engine.

Own autoload classes

If desired, the behavior described above can be overridden. To do this, override the core's GetClasses method. The method takes no parameters and must return a dictionary:

  • key — class name along with namespace
  • value — absolute path to the php-file

Model

A model is a set of classes that describe the business logic of an application.
It's recommended to place them in the subfolder classes of the core so the engine registers them in autoload.
It's recommended to use a single namespace with no nesting to make it convenient to refer to other classes.
A model class can be original or inherit any other class, but generally the model class is a descendant of SCRUD, describing the structure of and access to a database table.

Controllers

Controllers are a collection of classes that describe the order of access to the classes and methods of the model and (optionally) reduce the result of their execution to a view.
A controller class can be original or inherit any other class, but generally the controller class is a descendant of Unit and is located in the subfolder units of the core.
