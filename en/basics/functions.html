Global functions

The framework defines two global functions, available everywhere without a namespace or import. Both live in /BlackFox/functions and are guarded by function_exists(), so a project can safely redefine either of them earlier in the include chain.

T($variants)

Picks a translated string out of a dictionary keyed by language code. It reads the current language from \BlackFox\Engine::I()->GetLanguage() and returns the matching value; if the current language is missing from the dictionary, it falls back to the first value in the array.
This is the mechanism behind every translatable NAME/TITLE/message string you've seen throughout these docs (field names, exception messages, unit alerts, and so on).

$name = T([ 'en' => 'Title', 'ru' => 'Название', ]); throw new \BlackFox\Exception(T([ 'en' => 'Login must be specified', 'ru' => 'Укажите логин', ]));

$variants doesn't have to list every configured language — whichever key is missing just falls back to the first one, so it's safe to leave a string untranslated while a project only has one active language.

debug($data = [], $title = '', $mode = 'print_r', $target = '/debug.txt')

A lightweight global debug helper. It only does anything when the debug key in /config.php is set to true, and it's skipped entirely if the request carries a turn_off_debug (or TURN_OFF_DEBUG) key — handy for muting debug output on specific AJAX calls without turning debug off globally.

$modeBehavior
print_r (default)Renders print_r output into a hidden <textarea> on the page, toggled visible with Alt + ` (tilde/backtick key)
var_exportSame hidden textarea, using var_export output
var_dumpSame hidden textarea, using var_dump output
consoleEchoes a <script>console.log(...)</script> tag
logAppends to a file, path is $target relative to the server document root (default /debug.txt)
emailSends the dump via mail() to the address in $target
debug($user, 'user'); debug($SQL, 'query', 'console'); debug($payload, 'webhook', 'log', '/logs/webhook.txt');
