Install

  1. Setup server with PHP 7+ and (MySQL 8+ or MariaDB 10+ or Postgres 10+) environment
  2. Clone or download framework as a folder into your server root
  3. Copy all files from /BlackFox/.example/ into your server root
  4. Update /config.php with requisites of the database (more info)
  5. Launch the file /BlackFox/install.php using php console
  6. Configure your web server to route requests through /index.php — see Apache and Nginx below

There we go! Now you can log into admin panel (/admin/) with default requisites: Root@123456

Apache

BlackFox is a single front-controller framework: every request for a non-static file (a *.php file or a folder) must end up executed by /index.php, which parses $_SERVER['REQUEST_URI'] itself and decides what to show (see Engine::MakeContent()). Requests are never routed to individual .php files directly — that would let a raw request reach a content fragment or an admin script, bypassing the Engine's own routing and access checks.

On Apache this is already taken care of: the .htaccess file copied from /BlackFox/.example/ in step 3 (see it on GitHub) rewrites every request for a non-static path to /index.php and adds a trailing slash to folder-like URLs. All you need is mod_rewrite enabled and AllowOverride All (or at least FileInfo) for the site's directory.

Nginx

Nginx doesn't read .htaccess, so the same routing has to be described directly in the server block. Three things matter:

  1. a URL with no extension and no trailing slash must be redirected with one added — Engine::MakeContent() appends index.php straight onto a folder path with no separator in between, so /basics would otherwise resolve to the non-existent /basicsindex.php instead of /basics/index.php
  2. real static files (css/js/images/fonts/...) are served directly, without touching PHP
  3. everything else is passed to PHP as /index.php, regardless of the requested path
server { listen 80; server_name example.com; root /path/to/your/server/root; index index.php; # extension-less URLs must end with a slash before Engine sees them location ~ ^(?<slashless>/[^.]*[^./])$ { return 302 $slashless/; } # real static assets, served directly location ~* \.(?:css|js|jpe?g|png|gif|ico|svg|webp|woff2?|ttf|eot|mp4|webm|pdf|txt|html)$ { try_files $uri =404; expires 1d; access_log off; } # everything else goes through the single front controller location / { fastcgi_pass 127.0.0.1:9000; fastcgi_index index.php; include fastcgi_params; fastcgi_param SCRIPT_FILENAME $document_root/index.php; fastcgi_param SCRIPT_NAME /index.php; } }

fastcgi_pass needs something listening on the other end. On Linux that's normally php-fpm; PHP for Windows doesn't ship it, so run the bundled php-cgi.exe as a FastCGI server instead:

php-cgi.exe -b 127.0.0.1:9000

If you registered more than one root, a static file may physically live under a different root than the one requested — extend the try_files fallback chain with those paths too, e.g. try_files $uri /BlackFox/root$uri =404; (see Virtual root).
