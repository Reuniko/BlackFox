Unit

Abstract class BlackFox\Unit is an environment for creating controllers.

A descendant class lives in a file and folder of the same name, and also contains a subfolder views, which holds the views.
Any public method can be an action, and its parameters are filled from the user's request.
Multiple actions can run in sequence. Connecting a template+view can be disabled. Units can inherit from each other, and templates+views are inherited along with them.
By default: the action name is Default, the view name is Default (includes the file 'Default.php').

Actions

An action is a public method of the unit.
The unit runs actions in sequence, filling their parameters from the user request, which is generated by the GetRequest() method. If an action has a parameter without a default value and the user hasn't provided that value, the unit throws an exception.

The sequence of actions to run (as a list of strings) is produced by the method GetActions($request), returning a simple array (list) of strings.

It's usually a good idea to override this method; otherwise it works by default as follows:

  • if the user specified an 'action' or 'ACTION' key in the request, that action is added to the list of actions to run
  • if the user specified a 'view' or 'VIEW' key in the request, that action is added to the list too, otherwise the 'Default' action is added to the list.

There are three ways to complete an action:

  • return an array, a string, or null
  • throw an exception
  • call the Redirect() method

There are two kinds of actions: preliminary actions and the final action. The last element of the action list (from the method GetActions($request)) becomes the final action; all the others become preliminary actions.

namespace Example; class UnitNames extends \BlackFox\Unit { public function GetActions(array $request = []) { if ($request['ACTION'] == 'Rename') { return ['Rename', 'Default']; } return ['Default']; } // $page = $_REQUEST['page'] ?: 1 public function Default($page = 1) { if ($page < 1) { throw new \BlackFox\Exception("page must be positive"); } $RESULT['ELEMENTS'] = Names::I()->Select(['PAGE' => $page]); return $RESULT; } // $ID = $_REQUEST['ID'] // $new_name = $_REQUEST['new_name'] public function Rename($ID, $new_name) { if (!is_numeric($ID)) { throw new \BlackFox\Exception("id must be numeric"); } Names::I()->Update($ID, ['NAME' => $new_name]); $this->Redirect(null, "Rename successful"); } }

Preliminary actions

  • may attempt to change the internal state of the model
  • may prepare additional data for display
  • on success:
    • if the response is a string, it's aggregated into $ALERTS
    • otherwise the response is converted to an array and aggregated into $RESULT
  • on exception — the exception is caught and aggregated into $ALERTS (via the Error method)
  • on redirect — execution stops

Final action

  • should not attempt to change the internal state of the model
  • prepares the main data for display
  • on success — the response is converted to an array and aggregated into $RESULT
  • on exception — the exception is not caught, letting it bubble up to a level above
  • on redirect — execution stops

Connecting a template+view

If the final action completes without exceptions or errors, and the property $view is not empty, the unit takes the result and connects it to the corresponding view as a $RESULT variable.
By default, before running any actions, the Controller method sets the $view property to the name of the final action. If, during an action, you decide a different view should be connected, change the $view property.

Inheritance of templates+views

When it needs to connect a template+view, the unit first looks for it in its own folder: views/$view.php, then searches up through the view folders of its parents. This search happens in the Path($path) method. If you use it in your own view to connect sub-views, descendant units will be able to override your sub-views.

.../UnitExample/views/default.php /**@var \BlackFox\Unit $this */ /**@var array $RESULT */ foreach ($RESULT as $element) { // usual way, successors can't override 'element' view require 'element.php'; // better way, successor may override 'element' view require($this->Path('element.php')); }

The GetParentView() method returns the absolute path to the same view of the parent unit. It lets you augment the parent unit's view instead of completely redefining it.

.../UnitExample/views/element.php /**@var \BlackFox\Unit $this */ /**@var array $element */ ?> <div class="i_want_to_wrap_element"> <h3><?= $element['NAME'] ?></h3> <? require($this->GetParentView()); ?> </div>
