Unit

Абстрактный класс BlackFox\Unit представляет собой среду для создания контроллеров.

Класс-наследник находится в файле и папке с такими же названиями, а также содержит подпапку views, в которой находятся файлы-отображения.
Любой публичный метод является действием, а параметры к ним формируются из запроса пользователя.
Возможен запуск нескольких действий. Возможно отключить подключение шаблона+отображения. Возможно наследовать юниты друг от друга, при этом шаблоны+отображения тоже наследуются.
По умолчанию используется действие Default, отображение Default (подключает файл 'Default.php').

Действия

Действие — это публичный метод юнита.
Юнит последовательно запускает действия, формируя параметры из запроса пользователя, который формируется методом GetRequest().
Если у действия есть параметр без значения по умолчанию, а пользователь не указал это значение — юнит кидает исключение.

Последовательность выполняемых действий (в виде списка строк) формируется в методе GetActions($request).

Желательно переопределить этот метод, иначе он будет работать по умолчанию следующим образом:

  • если пользователь указал в запросе ключ 'action' или 'ACTION' — это действие будет добавлено в список выполняемых действий
  • если пользователь указал в запросе ключ 'view' или 'VIEW' — это действие будет добавлено в список выполняемых действий, иначе в список будет добавлено действие 'Default'.

Есть три способа завершить действие:

  • вернуть массив, строку или null
  • бросить исключение
  • использовать метод Redirect()

Действия делятся на две категории: предварительные действия и финальное действие. Последний элемент списка действий (из метода GetActions($request)) становится финальным действием, все остальные — предварительными.

namespace Example; class UnitNames extends \BlackFox\Unit { public function GetActions(array $request = []) { if ($request['ACTION'] == 'Rename') { return ['Rename', 'Default']; } return ['Default']; } // $page = $_REQUEST['page'] ?: 1 public function Default($page = 1) { if ($page < 1) { throw new \BlackFox\Exception("page must be positive"); } $RESULT['ELEMENTS'] = Names::I()->Select(['PAGE' => $page]); return $RESULT; } // $ID = $_REQUEST['ID'] // $new_name = $_REQUEST['new_name'] public function Rename($ID, $new_name) { if (!is_numeric($ID)) { throw new \BlackFox\Exception("id must be numeric"); } Names::I()->Update($ID, ['NAME' => $new_name]); $this->Redirect(null, "Rename successful"); } }

Предварительные действия

  • могут пытаться изменить внутреннее состояние модели
  • могут подготавливать дополнительные данные для отображения
  • успех — агрегирует ответ:
    • массив — в результат ($RESULT)
    • строку — в успешные сообщения ($ALERTS)
  • ошибка — ловит исключение и агрегирует его в $ALERTS (через метод Error)
  • редирект — прекращает выполнение

Финальное действие

  • не пытается изменить внутреннее состояние модели
  • подготавливает основные данные для отображения
  • успех — преобразует ответ в массив и агрегирует его в результат ($RESULT)
  • ошибка — не ловит исключение, позволяя ему всплыть на уровень выше
  • редирект — прекращает выполнение

Подключение шаблона и отображения

Если в результате выполнения финального действия не произошло ошибок, а также оказалось не пустым свойство $view, юнит берёт результат и подключает его в соответствующее отображение как переменную $RESULT.
По умолчанию, метод Controller, прежде чем выполнить действия, устанавливает свойство $view равным названию финального действия. Если в процессе выполнения действия выяснится, что необходимо подключить иное отображение, измените свойство $view.

Наследование шаблонов и отображений

При необходимости подключить отображение, юнит ищет его сперва в собственной папке views, затем идёт поиск вверх по папкам юнитов-родителей. Этот поиск происходит в методе Path($path). Если использовать его в собственных отображениях для подключения суб-отображений, это позволит юнитам-наследникам переопределять суб-отображения.

.../UnitExample/views/default.php /**@var \BlackFox\Unit $this */ /**@var array $RESULT */ foreach ($RESULT as $element) { // usual way, successors can't override 'element' view require 'element.php'; // better way, successor may override 'element' view require($this->Path('element.php')); }

Метод GetParentView() возвращает абсолютный путь к отображению юнита-родителя, которое можно подключить в отображении наследника, чтобы его дополнить, а не полностью переопределить.

.../UnitExample/views/element.php /**@var \BlackFox\Unit $this */ /**@var array $element */ ?> <div class="i_want_to_wrap_element"> <h3><?= $element['NAME'] ?></h3> <? require($this->GetParentView()); ?> </div>
