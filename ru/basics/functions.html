Глобальные функции

Фреймворк определяет две глобальные функции, доступные везде без неймспейса и подключения. Обе лежат в /BlackFox/functions и обёрнуты в проверку function_exists(), так что проект может безопасно переопределить любую из них раньше по цепочке подключения.

T($variants)

Выбирает переведённую строку из словаря, где ключ — код языка. Функция берёт текущий язык из \BlackFox\Engine::I()->GetLanguage() и возвращает соответствующее значение; если текущего языка нет в словаре — возвращает первое значение массива.
Именно на этом механизме построены все переводимые строки NAME/TITLE/сообщения, которые встречались во всей этой документации (названия полей, тексты исключений, алерты юнитов и т.д.).

$name = T([ 'en' => 'Title', 'ru' => 'Название', ]); throw new \BlackFox\Exception(T([ 'en' => 'Login must be specified', 'ru' => 'Укажите логин', ]));

$variants не обязан перечислять все языки, настроенные в проекте, — отсутствующий ключ просто заменится первым значением массива, так что можно оставить строку непереведённой, если в проекте активен только один язык.

debug($data = [], $title = '', $mode = 'print_r', $target = '/debug.txt')

Лёгкий глобальный помощник для отладки. Работает только если ключ debug в /config.php установлен в true, и полностью отключается, если в запросе присутствует ключ turn_off_debug (или TURN_OFF_DEBUG) — удобно, чтобы приглушить отладочный вывод для конкретных AJAX-запросов, не выключая отладку глобально.

$modeПоведение
print_r (по умолчанию)Выводит print_r в невидимую <textarea> на странице, отображается по нажатию Alt + ` (клавиша тильды/ё)
var_exportТа же невидимая textarea, но вывод var_export
var_dumpТа же невидимая textarea, но вывод var_dump
consoleВыводит тег <script>console.log(...)</script>
logДописывает в файл, путь $target относительно корня сервера (по умолчанию /debug.txt)
emailОтправляет дамп через mail() на адрес из $target
debug($user, 'user'); debug($SQL, 'query', 'console'); debug($payload, 'webhook', 'log', '/logs/webhook.txt');
