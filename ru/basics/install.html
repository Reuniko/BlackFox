Установка

  1. Установите веб-сервер с PHP 7+ и (MySQL 8+ или MariaDB 10+ или Postgres 10+) окружением
  2. Склонируйте или скачайте фреймворк в виде папки в корень сайта
  3. Скопируйте все файлы из /BlackFox/.example/ в корень сайта
  4. Укажите реквизиты подключения к базе данных в файле /config.php (подробнее)
  5. Однократно запустите файл /BlackFox/install.php с помощью командной строки PHP
  6. Настройте веб-сервер так, чтобы все запросы проходили через /index.php — см. Apache и Nginx ниже

Установка завершена! Теперь вы можете зайти в административный раздел (/admin/) используя реквизиты по умолчанию: Root@123456

Apache

BlackFox — фреймворк с единой точкой входа: любой запрос на не статичный файл (*.php или папку) должен в итоге исполняться файлом /index.php, который сам разбирает $_SERVER['REQUEST_URI'] и решает, что показать (см. Engine::MakeContent()). Запросы никогда не должны идти напрямую на отдельные .php-файлы — иначе запрос может добраться до фрагмента контента или админского скрипта в обход маршрутизации и проверок доступа самого Engine.

На Apache это уже настроено: файл .htaccess, скопированный из /BlackFox/.example/ на шаге 3 (посмотреть на GitHub), перенаправляет любой запрос на не статичный путь на /index.php и дописывает конечный слеш к запросам, похожим на папки. Всё, что нужно — включённый mod_rewrite и AllowOverride All (или хотя бы FileInfo) для директории сайта.

Nginx

Nginx не читает .htaccess, поэтому ту же маршрутизацию нужно описать прямо в конфиге server-блока. Важны три вещи:

  1. URL без расширения и без конечного слеша нужно перенаправлять, дописывая слеш — Engine::MakeContent() приклеивает index.php прямо к пути папки без разделителя между ними, поэтому запрос /basics без редиректа превратится в несуществующий /basicsindex.php вместо /basics/index.php
  2. реальные статичные файлы (css/js/картинки/шрифты/...) отдаются напрямую, без обращения к PHP
  3. всё остальное передаётся в PHP как /index.php, независимо от запрошенного пути
server { listen 80; server_name example.com; root /path/to/your/server/root; index index.php; # URL без расширения должны получить слеш ещё до того, как их увидит Engine location ~ ^(?<slashless>/[^.]*[^./])$ { return 302 $slashless/; } # реальные статичные файлы отдаются напрямую location ~* \.(?:css|js|jpe?g|png|gif|ico|svg|webp|woff2?|ttf|eot|mp4|webm|pdf|txt|html)$ { try_files $uri =404; expires 1d; access_log off; } # всё остальное идёт через единую точку входа location / { fastcgi_pass 127.0.0.1:9000; fastcgi_index index.php; include fastcgi_params; fastcgi_param SCRIPT_FILENAME $document_root/index.php; fastcgi_param SCRIPT_NAME /index.php; } }

fastcgi_pass должен указывать на что-то, что слушает порт. На Linux это обычно php-fpm; сборки PHP для Windows его не содержат, поэтому вместо него запускается штатный php-cgi.exe в режиме FastCGI-сервера:

php-cgi.exe -b 127.0.0.1:9000

Если у вас зарегистрировано больше одного корня, статичный файл может физически лежать не в том корне, что запрошен — добавьте эти пути и в цепочку try_files, например try_files $uri /BlackFox/root$uri =404; (см. Виртуальный корень).
