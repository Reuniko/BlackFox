Структура

Обычно, каждая папка в корне веб-сайта является ядром (но не обязательно).
Ядро — это набор из классов, юнитов, шаблонов и виртуального корня.
Фреймворк является ядром, ваша папка тоже будет являться ядром (её нужно создать), каждое ядро следует хранить в отдельных репозиториях.

В простом случае у вас будет всего два ядра, например: /BlackFox для фреймворка и /Site для вашего проекта.
Возможно добавление дополнительных ядер.
Все активные ядра нужно зарегистрировать в файле /config.php (ключ 'cores').

Внутри ядра могут содержаться следующие папки:

  • classes — содержит исходный код классов
  • units — содержит папки юнитов
  • root — виртуальный корень сервера
  • templates — содержит папки шаблонов

Ядро

Ядро — это структурная единица, представляющая из себя папку с файлом Core.php а также другими файлами, среди которых php-классы и прочие файлы. Имя ядра совпадает с именем папки и неймспейсом. Обычно используется один неймспейс верхнего уровня без вложенности.

Файл Core.php должен содержать в себе класс-наследник от BlackFox\ACore с именем {КодЯдра}\Core:

namespace Example; class Core extends \BlackFox\ACore { public function GetScheme() {/* ... */} public function Upgrade() {/* ... */} public function Load() {/* ... */} public function Menu() {/* ... */} }
GetScheme
должен вернуть экземпляр класса Scheme
Upgrade
вызывается при установке и изменении ядра, используется для синхронизации структуры таблиц и прочих поправок (смотри наследников для примера)
Load
вызывается всегда, если ядро активно
Menu
вызывается юнитом административного меню, должен вернуть массив, описывающий раздел административного меню (смотри наследников для примера)

Автозагрузка классов

По умолчанию ядро сканирует собственные подпапки classes и units, ищет в них любые php-файлы и регистрирует их как одноименные классы в неймспейсе ядра. Глубина сканирования различается:

  • classes — сканируются все подпапки, неограниченная вложенность
  • units — сканируется на одну подпапку вглубь

Таким образом, при разработке собственного ядра помещайте классы в подпапку classes, юниты в подпапку units, именуйте файлы так же, как именуется класс внутри них, тогда они будут автоматически зарегистрированы в движке.

Собственный автолоад классов

При желании вышеописанное поведение ядра можно переопределить. Для этого переопределите метод GetClasses ядра. Метод не принимает параметров и должен вернуть словарь классов:

  • ключ — имя класса вместе с неймспейсом
  • значение — абсолютный путь к php-файлу, описывающему класс

Модель

Модель — это набор классов, описывающих бизнес-логику приложения.
Рекомендуется располагать их в подпапке classes ядра, для того чтобы движок их зарегистрировал в автозагрузку.
Рекомендуется использовать один общий неймспейс первого уровня, для того чтобы обращение к другим классам того же ядра происходило напрямую без указания неймспейса.
Класс модели может быть оригинальным или наследовать любой другой класс, но как правило класс модели является наследником от SCRUD, описывающим структуру и доступ к таблице.

Контроллеры

Контроллеры — это набор классов, которые описывают порядок доступа к классам и методам модели и (не обязательно) сводят результат их выполнения к вьюшке.
Класс контроллера может быть оригинальным или наследовать любой другой класс, но как правило класс контроллера является наследником от Unit и располагается в подпапке units ядра.
